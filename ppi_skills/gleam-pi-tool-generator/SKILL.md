<essential_principles>
## Core Architecture

### Pi Extension Cannot Be Compiled From Gleam
Pi requires a specific JS structure: `export default function(pi) { pi.registerTool({...}) }`.
Gleam **cannot** compile directly to this — Pi won't accept `.gleam` or `.mjs` as an extension.
A **generated** `extension.js` file is required.

### The Generator Is a Cook, Not a Code Generator
The generator does NOT construct JS objects. It **composes text**:
1. Gleam types (`PiToolCall`, `PiEventHook`) carry tool and event metadata
2. Gleam functions (`to_js_text`, `event_hook_to_js`) convert that metadata to JS text strings
3. The generator concatenates all text into `extension.js`
4. Every ingredient is validated by `gleam build` before composition

### Two Gleam Types for Pi Extensions
1. **`PiToolCall`** — defines a Pi tool (name, description, parameters, handler)
2. **`PiEventHook`** — defines an event handler (tool_call, session_start, etc.)

Both are Gleam values. AIs write Gleam, Gleam compiles to JS. No raw JS editing possible.

### Zero Hand-Written JS Strings
**There are NO hand-written JS strings in the generator.** All JS text is mechanically generated from structured Gleam types (`FnArgument`, `ParamSrc`, `HookGuard`, `ResultFormat`).

The following types and functions have been **DELETED** and must NEVER be reintroduced:
- `FnArg`, `JsLiteral(String)`, `FromParam(String)` — replaced by `FnArgument` + `ParamSrc`
- `CustomJs(String)`, `custom_js()` — replaced by `Template(String)` only
- `lit()`, `from_param()`, `new_arg()` — replaced by structured constructors
- `guard: Option(String)` — replaced by `HookGuard`

### Single Source of Truth
`ppi.mjs` calls `generate()` — it never composes text itself.
`extension.js` is a build artifact — generated at every `ppi` start, never hand-edited.

### psypi Generates at Startup
`bin/ppi.mjs` imports the compiled generator `.mjs` directly — no `gleam run` needed at runtime.
The flow: `ppi` → import generator → `generate()` → write `extension.js` → spawn `pi -e extension.js`.
Every `ppi` start produces a fresh `extension.js` from the latest compiled Gleam code.

### Safety: AIs Write Gleam, Not JS
AIs can only define tools and event hooks as Gleam values (`PiToolCall`, `PiEventHook`).
The Gleam compiler validates everything. AIs cannot bypass it by writing raw JS.
Handler bodies for event hooks are generated by Gleam functions — not hand-written JS strings.
</essential_principles>

<quick_start>
## Quick Start: Add a New Pi Tool

1. **Define the Gleam function** (e.g., in `my_module.gleam`)
2. **Create a `PiToolCall` value** in that module (e.g., `my_module_tool()`)
3. **Import it in the generator** (`extension_generator.gleam`)
4. **Add it to `all_tools()` list**
5. **Build** (compile Gleam to JS)
6. **Run ppi** (auto-generates extension.js and starts Pi)

### Build (after changing Gleam source)

```bash
gleam clean && gleam build
```

### Run ppi

```bash
./bin/ppi.mjs
```

`ppi` auto-generates `extension.js` at startup and spawns Pi with the fresh extension.
</quick_start>
