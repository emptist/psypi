# Plan 01-03: Eliminate PiRawHook and PiRawCommand Escape Hatches

## Objective
Remove `PiRawHook` and `PiRawCommand` variants from the type system, and convert all their usages to proper typed variants (`PiEventHook` and `PiCommandReg`).

## Context
`PiRawHook` and `PiRawCommand` accept `handler_body: String` — raw JS strings that bypass the typed pipeline entirely. They are the root cause of the "fake Gleam" problem.

Current usages:
1. `before_agent_start` — `raw_event_hook_no_trigger("before_agent_start", before_agent_start_body_js())` — returns `{ systemPrompt: "..." }` to inject A-S role model
2. `agent_start` — `raw_event_hook("agent_start", "    // agent_start: S is starting, A stays silent\n")` — does nothing (just a comment)

## Tasks

### Task 1: Convert before_agent_start to proper PiEventHook
**Type:** refactor
**Files:** `src/hook_before_agent_start.gleam` (new), `src/extension_generator.gleam`, `src/pi_tool_call.gleam`
**Action:**
1. Create `src/hook_before_agent_start.gleam` with a Gleam handler function:
   ```gleam
   pub fn on_before_agent_start(ctx: a, pi: a) -> Result(String, String)
   ```
   This function:
   - Calls `event_hooks.record_trigger("before_agent_start")`
   - Returns the A-S role model system prompt string
2. Register it as a proper `PiEventHook`:
   ```gleam
   event_hook(
     "before_agent_start",
     "hook_before_agent_start",
     "on_before_agent_start",
     [lit("ctx"), lit("pi")],
     None,
     SilentSuccess,
     NotifyError,
   )
   ```
3. The `before_agent_start` hook in Pi returns `{ systemPrompt: "..." }` — this is a Pi Extension API feature. The generated JS needs to handle this return value specially. The `event_hook_to_js` generator for `PiEventHook` already wraps the result with `unwrapGleamResult`, but for `before_agent_start` the hook must return `{ systemPrompt: "..." }` not `{ content: [...] }`.

   **Problem:** The current `event_hook_to_js` generator doesn't know about `systemPrompt` return type. The `PiEventHook` type doesn't have a `result_format` field.

   **Solution:** Add a `HookResultFormat` type to `PiEventHook`:
   ```gleam
   pub type HookResultFormat {
     SilentResult
     SystemPromptResult
   }
   ```
   And add `result_format: HookResultFormat` field to `PiEventHook` and `PiDebouncedHook`.

   Then in `event_hook_to_js`, handle `SystemPromptResult` by returning `{ systemPrompt: r.value }` instead of the default behavior.

4. Remove `before_agent_start_body_js()` from `extension_generator.gleam`
5. Remove `raw_event_hook_no_trigger` from `pi_tool_call.gleam`

**Verify:** `gleam build` succeeds, `before_agent_start` hook works correctly

### Task 2: Convert agent_start to proper PiEventHook
**Type:** refactor
**Files:** `src/extension_generator.gleam`
**Action:**
The `agent_start` hook currently does nothing (just a comment). Convert it to a proper `PiEventHook` that calls a no-op Gleam handler, or remove it entirely if it serves no purpose.

Option A: Remove it (it does nothing)
Option B: Convert to `event_hook("agent_start", "hook_on_agent_start", "on_agent_start", [lit("ctx")], None, SilentSuccess, NotifyError)` with a no-op handler

**Preferred:** Option A — remove it. A no-op hook is dead code.

**Verify:** `gleam build` succeeds

### Task 3: Remove PiRawHook and PiRawCommand from type system
**Type:** refactor
**Files:** `src/pi_tool_call.gleam`, `src/extension_generator.gleam`
**Action:**
1. Remove `PiRawHook` variant from `PiEventHook` type
2. Remove `PiRawCommand` variant from `PiCommandReg` type
3. Remove `raw_event_hook()`, `raw_event_hook_no_trigger()`, `raw_command()` constructors
4. Remove `PiRawHook` and `PiRawCommand` pattern matching from `event_hook_to_js()` and `command_to_js()`
5. Remove `record_trigger: Bool` field from `PiRawHook` — this was only needed because raw hooks bypassed the automatic trigger recording. Proper `PiEventHook` always records triggers.

**Verify:** `gleam build` succeeds, all hooks and commands still work

4. Verify all hooks are proper `pi.on(...)` with Gleam module imports

**Done criteria:** No `PiRawHook` or `PiRawCommand` in codebase, no `handler_body` fields, no inline JS in hook/command registrations
