# Plan 01-02: Fix semantic_id() Global ID Format

## Objective
Change global ID from `G-A--source-model` to `A-G-source-model`. The `G` moves to the project position instead of before the prefix, because id_prefix must be `S` or `A` for DB lookups.

## Tasks

### Task 1: Fix semantic_id() in agent_identity_types.gleam
**Type:** refactor
**Files:** src/agent_identity_types.gleam
**Action:**
- Current: `global_prefix <> prefix <> "-" <> project <> "-" <> source <> "-" <> model`
  - When global: `"G-" <> "A" <> "-" <> "" <> "-" <> source <> "-" <> model` = `"G-A--source-model"`
- New: `prefix <> "-" <> project_or_G <> "-" <> source <> "-" <> model`
  - When global: `"A" <> "-" <> "G" <> "-" <> source <> "-" <> model` = `"A-G-source-model"`
- Remove `global_prefix` variable
- Use project name or "G" in the project slot: `case ctx.global { True -> "G" | False -> ctx.project }`

**Verify:** semantic_id with global=True produces `A-G-source-model` format

### Task 2: Fix duplicate semantic_id() in agent_identity.gleam
**Type:** refactor

- Apply same fix to agent_identity.gleam's version

**Verify:** Both modules produce consistent IDs

### Task 3: Fix get_enriched_identity() to use updated context
**Type:** bugfix
**Files:** src/agent_identity.gleam
**Action:**
- Current bug: `get_enriched_identity()` computes `project` and `_global` but never updates ctx before calling `semantic_id(ctx)`
- Fix: Build new IdentityContext with resolved project and global values before calling semantic_id

**Verify:** `gleam build` succeeds

**Done when:** Global IDs are `A-G-source-model` format, project IDs are `A-project-source-model` format
