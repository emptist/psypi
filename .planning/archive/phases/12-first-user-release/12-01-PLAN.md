    Create a new Gleam module `src/seed.gleam` that populates required initial data for a fresh database. This is the "first boot" data that makes psypi functional out of the box.

    The seed module should:
    1. Check if agent_souls has rows — if empty, insert A and S souls (from migration 008_agent_soul.sql)
    2. Check if psypi_config has `monitor_debounce_ms` — if missing, insert `300000` (5 min default)

    5. Check if agent_prefixes has rows — if empty, insert A, S, G prefixes
    6. Print what was seeded via io.println

    Use db.with_connection for each check/insert. Use INSERT ... ON CONFLICT DO NOTHING for idempotency.

    The seed should be safe to run multiple times (idempotent).

    Add a main() function that runs all seeds and returns promise.resolve(Ok(0)).

<task type="auto">
  <name>Task 3: Create setup.sh script</name>
  <files>bin/setup.sh</files>
  <action>
    Create `bin/setup.sh` — a one-command setup script for fresh users. It should:

    1. Check dependencies exist (node, gleam, pi, psql) — print install links if missing
    2. Check PostgreSQL is running (pg_isready) — try to start it if not
    3. Create `psypi` database if it doesn't exist (`createdb psypi`)
    4. Enable required extensions: `pgcrypto` (for gen_random_uuid), `vector` (for skill embeddings)
    5. Copy `.env.example` → `.env` if `.env` doesn't exist
    6. Run `gleam deps download`
    7. Run `rm -rf build/ && gleam build`
    8. Run `gleam run -m simple_migrate`
    9. Run `gleam run -m seed`
    10. Run `node bin/ppi.mjs --generate-only` (or equivalent to regenerate extension.js)
    11. Print success message with next steps

    Make it executable: `chmod +x bin/setup.sh`

    Handle macOS (brew) and Linux (apt/systemctl) for PostgreSQL.
    Use `set -e` to fail fast on errors.
    Use colored emoji output for clarity (✅ ❌ ⚠️ 📦).
  </action>
  <verify>bash bin/setup.sh runs from a clean state, all steps complete</verify>
  <done>setup.sh exists, is executable, handles all setup steps end-to-end</done>
