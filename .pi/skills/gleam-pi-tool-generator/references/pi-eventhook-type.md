# PiEventHook Type Reference

## Type Definition

```gleam
pub type PiEventHook {
  PiEventHook(
    event_name: String,   // e.g. "tool_call", "session_start", "agent_end"
    handler_body: String, // JS handler body as text (generated by Gleam function)
  )
}
```

## Purpose

`PiEventHook` defines a Pi event handler — it intercepts Pi lifecycle events like `tool_call`, `session_start`, `agent_end`, etc.

Unlike `PiToolCall` (which registers tools), `PiEventHook` registers event handlers via `pi.on('event_name', handler)`.

## Key Difference from PiToolCall

| Aspect | PiToolCall | PiEventHook |
|--------|------------|-------------|
| Registers | `pi.registerTool({...})` | `pi.on('event_name', handler)` |
| Purpose | User-facing tools | Event interception/hooks |
| Handler | Structured (parameters, execute) | Raw JS body (flexible) |
| Result format | RawJson, Template, CustomJs | Any JS code |

## Handler Body

The `handler_body` is JS text that goes inside the `pi.on()` callback. It must be generated by a Gleam function — never hand-written JS strings.

**Correct pattern:**
```gleam
fn my_hook() -> PiEventHook {
  PiEventHook(
    "tool_call",
    generate_handler_body(),  // Gleam function that returns JS text
  )
}

fn generate_handler_body() -> String {
  [
    "    if (event.toolName === 'edit') {",
    "      // ... JS code ...",
    "    }",
  ]
  |> list.map(fn(s) { s <> "\n" })
  |> string.concat
}
```

**Wrong pattern (don't do this):**
```gleam
// DON'T hand-write JS strings — AIs can mess up the syntax
PiEventHook("tool_call", "if (event.toolName === 'edit') { ... }")
```

## Example: Auto-Backup Hook

```gleam
// In extension_generator.gleam

fn auto_backup_hook() -> PiEventHook {
  event_hook("tool_call", auto_backup_handler_body())
}

fn auto_backup_handler_body() -> String {
  [
    "    if (event.toolName === 'edit' || event.toolName === 'write') {",
    "      const filePath = event.input?.path || event.input?.filePath;",
    "      if (!filePath) return;",
    "      try {",
    "        const fs = await import('fs');",
    "        const content = fs.readFileSync(filePath, 'utf-8');",
    "        const { save_version } = await import('...code_version.mjs');",
    "        const identity = await get_resolved_identity(false, _sessionId, 'psypi', '', '', 'psypi', '');",
    "        const r = unwrapGleamResult(identity);",
    "        if (r.ok) {",
    "          await save_version(filePath, content, r.value.id, '', 'auto-backup before ' + event.toolName);",
    "          ctx.ui.notify('Auto-backup: ' + filePath.split('/').pop(), 'info');",
    "        }",
    "      } catch (err) {",
    "        ctx.ui.notify('Auto-backup failed: ' + err.message, 'error');",
    "      }",
    "    }",
  ]
  |> list.map(fn(s) { s <> "\n" })
  |> string.concat
}
```

## Available Pi Events

Common events you can hook into:

| Event | When it fires |
|-------|---------------|
| `session_start` | New session started |
| `tool_call` | Before a tool executes (can block) |
| `tool_result` | After a tool returns |
| `agent_end` | Agent finishes a turn |
| `message_end` | A message is finalized |

See Pi extension docs for the full list.

## Adding a New Event Hook

1. Create a Gleam function that returns a `PiEventHook`:
```gleam
fn my_event_hook() -> PiEventHook {
  event_hook("tool_call", my_handler_body())
}

fn my_handler_body() -> String {
  [
    "    // Your JS code here",
    "    console.log('tool_call:', event.toolName);",
  ]
  |> list.map(fn(s) { s <> "\n" })
  |> string.concat
}
```

2. Import it in `extension_generator.gleam`:
```gleam
import psypi_cli/my_module.{my_event_hook}
```

3. Add to `all_event_hooks()`:
```gleam
pub fn all_event_hooks() -> List(PiEventHook) {
  [
    auto_backup_hook(),
    my_event_hook(),  // ← new
  ]
}
```

4. Build and run:
```bash
cd gleam/psypi_core && rm -rf build/ && gleam build
psypi
```

## Safety Rules

1. **Handler body must be generated by a Gleam function** — never hand-write JS strings
2. **Keep handler bodies small** — complex logic should be in Gleam modules, called from the handler
3. **Don't block tool calls unless necessary** — return early if the hook doesn't apply
4. **Catch errors silently** — event hooks should never crash the extension
