# Add a New Event Hook

## Required Reading
- `references/pi-eventhook-type.md` — PiEventHook type and patterns
- `references/architecture.md` — Generator architecture

## Process

### Step 1: Create the Hook Function

In a Gleam module (e.g., `my_module.gleam`), create a function that returns a `PiEventHook`:

```gleam
import psypi_cli/pi_tool_call.{PiEventHook, event_hook}

pub fn my_hook() -> PiEventHook {
  event_hook("tool_call", my_handler_body())
}

fn my_handler_body() -> String {
  [
    "    if (event.toolName === 'edit') {",
    "      // Your JS code here",
    "      console.log('Editing:', event.input?.path);",
    "    }",
  ]
  |> list.map(fn(s) { s <> "\n" })
  |> string.concat
}
```

**IMPORTANT**: The handler body must be generated by a Gleam function. Never hand-write JS strings.

### Step 2: Import in Generator

In `extension_generator.gleam`:

```gleam
import psypi_cli/my_module.{my_hook}
```

Add to `all_event_hooks()`:

```gleam
pub fn all_event_hooks() -> List(PiEventHook) {
  [
    auto_backup_hook(),
    my_hook(),  // ← new
  ]
}
```

### Step 3: Build and Test

```bash
cd gleam/psypi_core
rm -rf build/ && gleam build
psypi
```

### Step 4: Verify

Check that the hook is in the generated `extension.js`:

```bash
grep "pi.on('tool_call'" src/agent/extension/extension.js
```

## Common Mistakes

- **Hand-writing JS strings** — always use Gleam string concatenation
- **Forgetting to add to `all_event_hooks()`** — the hook won't be emitted
- **Blocking tool calls** — only block if absolutely necessary; use `{ block: true, reason: "..." }`
- **Not catching errors** — event hooks should never crash the extension

## Success Criteria
- [ ] Hook defined as `PiEventHook` value in Gleam
- [ ] Handler body generated by Gleam function (not hand-written JS)
- [ ] Imported in `extension_generator.gleam` and added to `all_event_hooks()`
- [ ] `rm -rf build/ && gleam build` succeeds
- [ ] `psypi` starts without error
- [ ] Hook appears in generated `extension.js`
