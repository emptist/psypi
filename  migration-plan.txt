# Critical Migration Plan – Smart Order of Fixes

## Goal
Enable full dynamic `project_id` resolution from `ctx.cwd` and restore a clean, buildable codebase while preserving all existing functionality.

## Guiding Principles
1. **Fix foundational infrastructure first** – the project resolution layer must work before any tool can use it.
2. **Commit after each successful build** – guarantees a known‑good state and easy rollback.
3. **Address the most urgent semantics** – A‑S shifting, inter‑review flow, and then peripheral tools.
4. **Preserve type safety** – all enums (IssueStatus, TaskStatus, SkillSource, MeetingStatus) must align with DB CHECK constraints.
5. **No hand‑written JS** – only use Gleam/F molecules and the `extension_generator`.

## Risks & Mitigations
| Risk | Mitigation |
|------|------------|
| Introducing a syntax error that blocks the build | Always run `gleam build` before committing; if it fails, revert the last edit and fix the underlying issue. |
| Project resolution returning an unexpected error | Add exhaustive logging in `project.resolve_or_create(cwd)` and unit‑test with a known fixture path. |
| Missing enum value causing DB CHECK violation | Keep the enum ↔ DB mapping tables in sync; run `psypi‑issue‑count` etc. to verify. |
| Breaking the A‑S shifting mechanism | Keep the old in‑memory fallback temporarily, then remove it only after Phase 3 passes. |
