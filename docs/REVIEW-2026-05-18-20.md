## 二、改错了（需要修复）

### 1. `tool_commit.gleam` — `pi_send_message(ctx,...)` 参数错误

`3fbc875` 把 `call_monitor` 替换为 `pi_send_message`，但第一个参数传了 `ctx` 而不是 `pi`：

```gleam
pi_send_message(ctx, "autonomic-wakeup", review_request, "persistent")
```

`pi_send_message` 的签名是 `(pi, type, content, display)`，传 `ctx` 会导致运行时错误。**至今未修复。**

### 2. `command_listen.gleam` — 同样用死文字替代 AI 思考

`080e03a` 把 `call_monitor` 替换为：
```gleam
let listen_msg = "[from A-worker:] DIRECT MESSAGE TO MONITOR\n\n"
  <> "The human says: " <> args
  <> "\n\nRespond as Monitor — a senior technical advisor. Be concise and helpful."
pi_send_message(pi, "autonomic-wakeup", listen_msg, "persistent")
```

这是把人类消息包装成死文字发给 S，而不是让 A 自己思考后回复。A 完全被绕过了。

### 3. `pi_extension_ffi.mjs` — `pi_send_message` 的 content 格式

`f6a515a` 修改了 `pi_send_message`：
```js
content: [{ type: 'text', text: String(content) }],
```
但之前已经修过一次（从字符串改为数组），后来又发现需要 `deliverAs: 'steer'`。这个函数的参数格式经历了多次修改，每次都只修一半。

### 4. `pi_extension_ffi.mjs` — `console.error` 诊断日志

`f6a515a` 加了 `console.error('[DIAG:pi_extension_ffi] MODULE LOADED')`，`964b31c` 加了 6 条 `console.error('[DIAG:callMonitor]...')`。这些在 Pi TUI 中不可见，只污染 stderr。今天工作区才删掉。

### 5. `directive.gleam` — `get_active_directives` 的 `dynamic.classify` 错误

`get_active_directives` 用 `dynamic.classify(row)` 提取 directive_text，但 `dynamic.classify` 返回的是类型描述字符串（如 `"String"`），不是实际值。这个 bug 从创建至今未修。

## 六、总结

**模式**：AI 不理解架构就动手改代码，改完发现不对就撤回或再改，形成"改-撤-改"循环。最典型的就是 `call_monitor` 的三进三出和 `inner/permanent` 的四步 rename。

**根因**：AI 把"消除问题症状"当成"解决问题"。`080e03a` 删 `call_monitor` 是因为 `call_monitor` 有 bug，但正确做法是修 bug，不是删功能用死文字替代。

**最大教训**：绝不能用硬编码字符串替代 AI 的自主思考。每次这么做，都是在把智能系统降级为脚本。
