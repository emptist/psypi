## Gleam Official FFI Standard (from local docs)

Source: `/Users/jk/gits/hub/tools_ai/refers/gleam-language/website/documentation/externals-guide.djot`

### Core Rule

> **"Externals should be used sparingly. Always prefer Gleam based solutions, using externals only when there is no suitable alternative for your needs and development constraints."**

### When FFI Is Justified

1. **You need to use an API provided by the runtime.** For example, getting memory usage statistics from the virtual machine.
2. **There is code written in another language on the runtime you are using which implements functionality you need, and your budget and deadlines mean it is impractical to implement the functionality in Gleam.**

### Before Writing FFI, Must Check

> "In these cases check there is no existing Gleam package that provides the functionality you need. This may solve the problem while providing a better developer experience."

### FFI Disadvantages

> - The external code written in other languages cannot be analysed and type checked by the Gleam compiler, making bugs and runtime errors possible.
> - The Gleam language server cannot work with languages other than Gleam, so you will have less editor assistance when working with external code in other languages.
> - External code can make it challenging or impossible to run your Gleam project on both the Erlang and JavaScript target.

### JavaScript FFI Syntax

```gleam
@external(javascript, "./my_app/pokemon.mjs", "badge_count")
pub fn pokemon_badge_count() -> Int
```

- Module path is relative to the `.gleam` file
- Node.js requires `.mjs` extension
- npm packages can be used directly: `@external(javascript, "has-flag", "hasFlag")`
- Type annotations are NOT optional for external functions

### Gleam Fallbacks

A function can have both a Gleam body AND an `@external` declaration. The external version is used when compiling to that target; the Gleam body is the fallback for other targets.

### API Design Rule

> "When using externals it may be tempting to create a Gleam API that imitates the API of the external code being used, but this is most often a mistake... Always design your APIs with Gleam in mind, no matter how they are implemented internally."

### Gleam-JS Type Mapping

| Gleam | JavaScript |
|---|---|
| `Bool` | `true`/`false` |
| `Int` | `number` (must be whole) |
| `Float` | `number` |
| `String` | `string` |
| `Nil` | `undefined` |
| `Result.Ok(v)` | `{ 0: v }` with constructor name `Ok` |
| `Result.Error(e)` | `{ 0: e }` with constructor name `Error` |
| `List` | Custom `List$Empty()`/`List$NonEmpty(head, tail)` |
| `BitArray` | `BitArray$BitArray(new Uint8Array([...]))` |

## Architecture Context

### A/S Bot Workflow

1. **S-bot** works on tasks, commits with `psypi-commit` (appends agent ID to message)
2. When S-bot goes idle, `hook_on_agent_end` detects it after debounce period
3. **A-bot** wakes up, reviews S-bot's commits since `last_a_session_at`
4. A-bot does inter-review (saves to DB), checks `agent_jobs` for more work
5. A-bot sends message to wake S-bot, records `last_a_session_at` to DB

### Config System (post-fix)

| `last_a_session_at` | `` | `a_orchestrator.gleam` | `a_db_reader.gleam` |
| `last_wakeup` | `` | `seed.gleam` | (currently unused) |

### Agent ID Format

`{prefix}-{project|G}-{source}-{model}[-{thinking_level}]`

- prefix: `S` (active) or `A` (idle)
- project: directory name, or `G` if no `.git` directory
- source: `ctx.model.provider` (e.g., `openrouter`)
- model: `ctx.model.id` (e.g., `anthropic/claude-sonnet-4`)
- thinking_level: `ctx.model.thinkingLevel` (optional)

Computed by `agent_identity.compute_id()` — pure Gleam, no FFI for the logic.

## Hook Registration Mechanism

Hooks are registered in `extension_generator.gleam` using helper functions:

```gleam
// Debounced hook — waits for debounce period before firing
debounced_hook(
  "agent_end",           // Pi event name
  "hook_on_agent_end",   // Gleam module name
  "on_agent_end",        // Gleam function name
  [lit("ctx"), lit("pi")],  // Arguments passed from Pi
  "psypi_config",        // Config module for debounce value
  "get_debounce_ms",     // Config function for debounce value
  None,                  // No custom debounce override
  SilentSuccess,         // On success: don't notify
  NotifyError,           // On error: notify user
)

// Event hook — fires immediately
event_hook(
  "tool_result",
  "hook_on_tool_result",
  "on_tool_result",
  [from_param("JSON.stringify(event.result || '')"), from_param("event.toolName || ''"), lit("pi")],
  None,
  SilentSuccess,
  NotifyError,
)
```

The `debounced_hook` function generates JS code that:
1. Listens for the Pi event
2. Starts a timer with the debounce value from `psypi_config.get_debounce_ms()`
3. Resets the timer if the event fires again
4. Calls the Gleam function when the timer expires

This means the debounce timer is set up in the generated `extension.js`, NOT in `hook_on_agent_end.gleam`. The Gleam hook only fires AFTER the debounce period has elapsed.

```gleam
import a_context_utils
import a_db_reader
import a_orchestrator
import gleam/int
import gleam/javascript/promise
import gleam/string
import pi_extension.{
  ctx_get_context_usage_json, ctx_get_cwd, ctx_get_entries_json,

  pi_send_message,
}
import psypi_config

pub fn on_agent_end(ctx: a, pi: b) -> promise.Promise(Result(Nil, String)) {
  notify_info(ctx, "[AUTONOMIC] on_agent_end FIRED — debounce elapsed, entering handler")
  case ctx_is_idle(ctx), ctx_has_pending_messages(ctx) {
    False, _ -> {
      notify_info(ctx, "[AUTONOMIC] S is not idle — clearing idle_since")
      let _ = psypi_config.set("idle_since", "0")
      promise.resolve(Ok(Nil))
    }
    True, True -> {
      notify_info(ctx, "[AUTONOMIC] S is idle but has pending messages — skipping")
      promise.resolve(Ok(Nil))
    }
    True, False -> {
      notify_info(ctx, "[AUTONOMIC] S is idle and no pending messages — checking idle_since")
      check_idle_since(ctx, pi)
    }
  }
}

fn check_idle_since(ctx: a, pi: b) -> promise.Promise(Result(Nil, String)) {
  promise.await(psypi_config.get("idle_since"), fn(result) {
    case result {
      Error(_) -> {
        let now = now_ms()
        let _ = psypi_config.set("idle_since", int.to_string(now))
        notify_info(ctx, "[AUTONOMIC] idle_since recorded: " <> int.to_string(now))
        promise.resolve(Ok(Nil))
      }
      Ok("0") -> {
        let now = now_ms()
        let _ = psypi_config.set("idle_since", int.to_string(now))
        notify_info(ctx, "[AUTONOMIC] idle_since recorded: " <> int.to_string(now))
        promise.resolve(Ok(Nil))
      }
      Ok(idle_since_str) -> {
        case int.parse(idle_since_str) {
          Error(_) -> {
            notify_info(ctx, "[AUTONOMIC] idle_since parse error — resetting")
            let _ = psypi_config.set("idle_since", "0")
            promise.resolve(Ok(Nil))
          }
          Ok(idle_since) -> {
            let now = now_ms()
            let elapsed = now - idle_since
            check_debounce(ctx, pi, elapsed)
          }
        }
      }
    }
  })
}

fn check_debounce(ctx: a, pi: b, elapsed: Int) -> promise.Promise(Result(Nil, String)) {
  promise.await(psypi_config.get_debounce_ms(), fn(debounce_result) {
    let debounce_ms = case debounce_result {
      Ok(ms) -> ms
      Error(_) -> 300000
    }
    case elapsed >= debounce_ms {
      True -> {
        notify_info(ctx, "[AUTONOMIC] debounce satisfied: elapsed=" <> int.to_string(elapsed) <> "ms >= " <> int.to_string(debounce_ms) <> "ms")
        let _ = psypi_config.set("idle_since", "0")
        let entries_json = ctx_get_entries_json(ctx)
        coordinate_with_s(ctx, pi, entries_json)
      }
      False -> {
        notify_info(ctx, "[AUTONOMIC] debounce NOT satisfied: elapsed=" <> int.to_string(elapsed) <> "ms < " <> int.to_string(debounce_ms) <> "ms")
        promise.resolve(Ok(Nil))
      }
    }
  })
}

fn coordinate_with_s(ctx: a, pi: b, entries_json: String) -> promise.Promise(Result(Nil, String)) {
  let usage_json = ctx_get_context_usage_json(ctx)
  let cwd = ctx_get_cwd(ctx)
  case ctx_is_idle(ctx) {
    False -> {
      notify_info(ctx, "[AUTONOMIC] S became busy during coordination — aborting")
      promise.resolve(Ok(Nil))
    }
    True ->
      promise.await(a_db_reader.is_s_still_idle(), fn(idle_result) {
        case idle_result {
          Ok(False) -> {
            notify_info(ctx, "[AUTONOMIC] S is busy (DB check) — skipping wake-up")
            promise.resolve(Ok(Nil))
          }
          _ -> coordinate_when_idle(ctx, pi, entries_json, usage_json, cwd)
        }
      })
  }
}

fn coordinate_when_idle(
  ctx: a, pi: b, entries_json: String, usage_json: String, cwd: String,
) -> promise.Promise(Result(Nil, String)) {
  case a_context_utils.parse_context_window(usage_json) {
    Error(e) -> {
      let msg =
        "[A-agentbot] <ERROR> parse_context_window failed: "
        <> e <> ". Fix parse_context_window in a_context_utils.gleam. Raw JSON: "
        <> string.slice(usage_json, 0, 300)
      pi_send_message(pi, "autonomic-error", msg, "persistent")
      promise.resolve(Ok(Nil))
    }
    Ok(context_window) ->
      a_orchestrator.run_a_workflow(ctx, pi, entries_json, usage_json, cwd, context_window)
  }
}
```

## simplifile API Reference (from local deps)

Source: `build/packages/simplifile/src/simplifile.gleam`

```gleam
pub fn read(from filepath: String) -> Result(String, FileError)
pub fn write(to filepath: String, contents contents: String) -> Result(Nil, FileError)
```

**IMPORTANT:** These are all synchronous (return `Result`, not `promise.Promise`). This is because `simplifile` uses `Sync` Node.js APIs on the JS target.

The `FileError` type has ~50 variants (all POSIX errno codes) plus `NotUtf8` and `Unknown(String)`. Always use `simplifile.describe_error()` to convert to human-readable string — do NOT try to match all variants manually.

## Potential Pitfalls for Next Session

1. **`simplifile.read()` is synchronous** but `hook_on_tool_call.gleam`'s `on_tool_call` returns `promise.Promise`. This is fine — you can return `promise.resolve(Ok(Nil))` wrapping a sync call.

2. **`simplifile.is_directory()` is synchronous** but `agent_identity.gleam`'s `compute_id` is also synchronous. This is fine — no promise wrapping needed.

3. **Path separator:** `simplifile.is_directory(cwd <> "/.git")` uses `/`. On macOS/Linux this works. The `filepath` package is in deps if cross-platform is needed, but psypi only runs on macOS.

4. **`psypi_config.set` returns `promise.Promise(Result(Nil, ConfigError))`** but many call sites use `let _ = psypi_config.set(...)` ignoring the result. This is intentional — config writes are fire-and-forget in the hook context.
