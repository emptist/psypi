## What Was Done

### 1. PiToolCall Type System

Created a Gleam type system for defining Pi tools as Gleam values:

**File**: `gleam/psypi_core/src/psypi_cli/pi_tool_call.gleam`

- `PiToolCall` type — carries all Pi Extension API metadata (name, description, params, module, fn_name, args, result_format)
- `PiParam` — parameter schema (name, type, required)
- `FnArg` — function arguments (JsLiteral for hardcoded values, FromParam for tool params)
- `ResultFormat` — output formatting (RawJson, Template, CustomJs)
- `to_js_text(tool)` — converts PiToolCall to JS source text
- `to_import_line(tool)` — generates import statement

Each module exports `PiToolCall` values:
- `agent_identity.gleam` → `my_id_tool()`, `partner_id_tool()`
- `task.gleam` → `task_add_tool()`, `task_list_tool()`

### 2. Extension Generator

**File**: `gleam/psypi_core/src/psypi_cli/extension_generator.gleam`

Rewritten as a text composer (cook):
- Collects all `PiToolCall` values via `all_tools()`
- Composes JS text: imports + helpers + tool registrations
- Writes to `extension.js` via `simplifile.write`

Key design: **everything is text**. The generator never constructs JS objects.

### 3. Bug Fix: "pi is not defined"

**Root cause**: `pi.on('session_start', ...)` was emitted outside `export default function(pi)`.

**Fix**: All helpers (`unwrapGleamResult`, `_sessionId`, `pi.on`) now emitted **inside** the factory function.

**File**: `gleam/psypi_core/src/psypi_cli/extension_generator.gleam`

Both `generate()` and `write_extension()` use the same composition order:
```
imports + "export default function(pi) {\n" + helpers + tools + "}\n"
```

### 4. Path Handling

**Critical**: Use relative paths directly with `simplifile.write`. Do NOT use `path.join(absolute, relativePath)` — this causes path doubling when relative path contains `..` segments.

Write path: `"../../src/agent/extension/extension.js"` from `gleam/psypi_core/`

### 5. Build Cache Issue

After editing Gleam source, `gleam run` sometimes uses stale compiled output from `build/`.

**Fix**: Always clean build after changes:

## How to Add a New Pi Tool

1. Define the Gleam function in its module
2. Create a `PiToolCall` value in that module (e.g., `my_tool()`)
3. Import it in `extension_generator.gleam`
4. Add to `all_tools()` list
5. Run:
```bash
cd gleam/psypi_core
rm -rf build/ && gleam build
gleam run -m psypi_cli/extension_generator
```
6. Verify `src/agent/extension/extension.js` has the new tool

## Key Rules

1. **Never hand-edit `extension.js`** — it's 100% generated
2. **Always `rm -rf build/` before `gleam build`** after source changes
3. **All `pi.*` calls must be inside `export default function(pi)`**
4. **Use relative paths** with `simplifile.write`, never `path.join(absolute, relative)`
5. **Gleam `test/` directory** (singular) for Gleam tests — standard convention
6. **`gleam/` prefix** in imports is for stdlib only — external packages use bare names
